# Mobile performance follow-up

## Production Mobile Lighthouse

Built with `npm run build`, served with `npm run preview`, then audited with Lighthouse 12.8.2 in Mobile mode using simulated throttling at a 412 x 823 viewport. The checked-in `screenshots/lighthouse-report.report.json` is a Desktop report; it does not verify the reported Mobile score of 73.

The reported 73 was not reproducible in a clean local production audit. The baseline and final Mobile runs both scored 100 in all four categories. The successful paired measurements were:

| Mobile production run | Performance | Accessibility | Best Practices | SEO | FCP | LCP | TBT | CLS | Speed Index |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Before | 100 | 100 | 100 | 100 | 1.3 s | 1.4 s | 10 ms | 0 | 1.3 s |
| After | 100 | 100 | 100 | 100 | 1.1 s | 1.3 s | 0 ms | 0 | 1.2 s |

The before report identified the 2.9 KiB stylesheet as render-blocking, with an estimated 150-165 ms saving. I added a Vite build plugin to inline that stylesheet into the single HTML page. The final report has no render-blocking resource, no CSS network request, and about 200 ms faster FCP, 100 ms faster LCP, and 100 ms faster Speed Index in this run. The transferred HTML grew from 884 bytes to 3,106 bytes; removing the 2,868-byte CSS request reduced total transfer by about 646 bytes. CLS stayed at zero and the four Lighthouse category scores stayed at 100.

The report still estimates 42 KiB of unused JavaScript from a 71.8 KiB JS transfer. Unused CSS passes. The LCP element is the page heading; the after run's breakdown measured about 26 ms to first byte and 541 ms of element render delay. No custom fonts, audio files, large images or third-party scripts are loaded. Audio is generated by Web Audio after user interaction. The remaining unused-JS estimate did not lower the score; splitting the required interactive app code was not justified by this audit.

## Console errors

`gads-scrapper.js` and `onboarding.js` and the reported error strings do not occur in `src/`, `index.html`, `vite.config.ts` or `package.json`. Neither script appears in the production request list. The clean Lighthouse run passes `errors-in-console`. The evidence indicates those errors are injected by a browser extension or other browser integration, not emitted by this app; the filenames alone do not identify which extension.

## Verification

`npm run lint`, `npm run typecheck` and `npm run build` pass. The JS bundle hash stayed unchanged across the CSS delivery change, so drum pad, keyboard, audio, history and meter logic did not change. No screenshots were captured or added for this follow-up.
